# 무료 캘린더 결과 수집

## 동작

- `scripts/refresh-quotes.mjs`가 시작될 때 `refreshCalendar()`를 먼저 호출한다. 기존 Windows 작업 `CGPORTFOLIO 시세 갱신`은 6시간 주기(PT6H)이며 2026-09-21 읽기 전용 조회로 확인했다. 별도 유료 서비스나 Codex 예약은 없다.
- 캘린더 실패를 로그로 남긴 뒤 시세 갱신은 계속한다. 별도 수동 실행: `npm run calendar:refresh`. 일부 원천 실패가 있으면 종료 코드 1이다.
- `data/calendar.json`은 일정 원본, `data/calendar-results.json`은 결과 캐시다. 둘 다 gitignore 대상. 수집기는 일정 원본을 변경하지 않는다.
- `.calendar-refresh.lock`으로 중복 실행을 막고, 최종 저장 시 공통 데이터 잠금·원자적 파일 교체·이전 파일 백업을 사용한다. 원천 실패 시 같은 대상의 기존 값과 마지막 성공 시각을 보존한다.
- 페이지는 동적 렌더이며 새로고침 시 최신 파일을 읽는다. 열어 둔 브라우저에 실시간 푸시하는 구조는 아니다. PC가 꺼져 있으면 수집하지 못한다.

## 일정 설정

`resultSource.period`는 발표일이 아닌 **관측 대상 월**이다. 기업은 **회계 분기 종료 월**이다. 설정되지 않은 일반 경제지표·배당·개인 일정은 기존대로 표시한다.

```json
{"id":"jobs-example","date":"2026-10-02","title":"미국 9월 고용보고서","kind":"macro","resultSource":{"provider":"bls","period":"2026-09"}}
```

```json
{"id":"earnings-example","date":"2026-10-28","title":"Microsoft 분기 실적","kind":"earnings","symbolId":"MSFT","resultSource":{"provider":"sec","period":"2026-09","cik":"0000789019"}}
```

위 날짜는 설정 형식 예시이지 공식 발표일 검증 결과가 아니다. 기존 운영 일정의 고용보고서 및 TSM/MSFT/AAPL/NVDA 네 기업에 수집 대상을 연결했다. **새 일정 생성·발표일 자동 검증은 이번 범위에 포함되지 않는다.** 새 이벤트에는 대상 기간을 명시해야 한다.

## 원천·계산 기준

- BLS 무료 공개 API: `CES0000000001` 비농업 고용 총원(천 명)의 월간 차이, `LNS14000000` 실업률(%), `CES0500000003` 민간 전체 시간당 평균임금의 전월비(%). 모두 계절조정 계열. 한 번의 POST로 세 계열을 수집한다. 최신 수정치를 표시하며 발표 전의 실제값은 null이다.
- SEC Company Facts: 표준 US-GAAP/IFRS의 매출·희석 EPS, 분기 길이 70~105일인 관측치만 사용. 같은 태그·통화의 전분기 및 전년 동기를 비교한다. 누적 6/9/12개월 수치는 분기로 쓰지 않고, EPS를 누적값 차감으로 추정하지 않는다. 표준 분기 태그가 없는 연말/외국기업 실적은 누락될 수 있다. EPS는 시장 예상치·조정 EPS·ADR 환산치가 아니다.
- `firstObserved`는 우리 프로그램의 최초 수집값이며 공식 최초 발표치가 아니다. 이후 수정치와 달라지면 UI에 구분 표시한다.
- 숫자 미수집은 `—`, 0은 실제 0으로 표시한다. % 지표의 차이는 %p. 큰 매출은 만/억 단위로 반올림 표시하고 값 위 툴팁에 원래 금액을 둔다.

## 연결 제한 및 보안

- 2026-09-21 실수집: BLS 성공, SEC 네 기업은 HTTP 403. SEC 응답은 `Undeclared Automated Tool` 안내다. 연결 성공으로 간주하면 안 된다.
- `.env.local`의 선택 항목 `SEC_USER_AGENT`에 프로젝트명 및 사용자가 명시적으로 제공한 연락 이메일을 지정할 수 있다. 이 값은 SEC에 전송된다. 이메일을 임의로 만들거나 다른 개인 설정에서 가져오지 않는다. 등록해도 IP/원천 제한의 해제는 보장되지 않는다.
- 이 환경의 Windows 신뢰 인증서를 Node HTTPS 요청에 추가하며 TLS 인증서 검증은 유지한다. Node 24 런타임에서 검증했다. 인증서 검증 비활성화나 차단 우회는 하지 않는다.
- 요청 간 간격, 15초 타임아웃, 응답 크기 한도, 같은 원천 중복 호출 제거를 적용했다. 유료 API 키·결제·로그인 정보 전송은 없다.

## 운영 반영

소스와 독립 수집 스크립트는 수정됐지만 운영 Next 서버(3000)는 재시작하지 않았다. 기존 예약 스크립트는 다음 실행부터 새 수집 코드를 읽는다. **변경된 화면은 운영 재빌드·재시작 후 표시된다.** 검증용 빌드는 별도 경로에서 수행했고 임시 설정은 원복했다.
